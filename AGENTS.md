# AGENTS.md: Data Center

Instructions for AI coding tools (Codex, Cursor, Claude Code and others) and a quick orientation for people. Read this before changing anything.

Space Engineers 2 mod: server racks, rack-mount servers, cable trays and room pieces for data-centre builds. GPL-3.0.

## Layout

- `Assets/DataCenter/` game-format block definitions (`.def`, `.partialdef`, `.meta`), models, icons. Generated by the pipeline below and installed by `install.sh`; not hand-edited. Models are tracked with Git LFS (see `.gitattributes`).
- `Source/Model/` the Blender pipeline: `build_dc.py`, the `dc/` Python package (catalogue, cloning, damage, KVM, trays, integration), `integration/` (staging and `install.sh`).
- `Scripts/` optional C# layer (`Client/`, `Simulation/`), only loaded with the game flag `-loadScripts`.
- `Tests/` pytest suite, plus `CoreTests/` and `CompileCheck/` (C#).
- `docs/workshop/` Workshop text and thumbnail. `README.md`, `CHANGELOG.md`; contributor docs in `docs/` (`model-pipeline.md`, `testing-in-game.md`, `triangle-budgets.md`).
- `Content/`, `.hashescache*`, `.referencescache*` are build output and ignored.

## Build and test

```bash
python3 -m pytest -q Tests -m "not build and not sdkbuild"                  # offline tests
blender -b --python Source/Model/build_dc.py -- all --no-render             # models (needs Blender 5.x)
python3 Source/Model/build_integration.py && bash Source/Model/integration/install.sh        # stage, then dry-run install
pgrep -x Modern.bin; python3 ../../tools/scripts/se2mod.py build DataCenter  # SDK build (game closed)
```

Pytest markers: `build` needs a prior Blender build, `sdkbuild` runs the real SDK build (opt-in with `DC_SDK_BUILD=1`), `scripts` needs `Scripts/`. Some tests import `se2model` from `../../tools`, which exists only in the maintainer's workspace; on a bare clone those modules fail to collect.

`scripts/test.sh` runs the offline checks. CI runs the same on GitHub-hosted runners, which have no game, SDK or Blender.

## Code style

- Python 3.11+, 4-space indent, 120 columns, standard library plus Blender's `bpy` where needed. Follow the neighbouring file.
- Comments say why, not what. Docs and messages in plain language; no marketing words.
- C# in `Scripts/` follows the game's script API; keep it small and read-only where possible.
- Every modelled part must have a believable purpose in the real thing and fit the block.

## Rules for this repo's data and assets

- Edit generators in `Source/Model/dc/`, rerun the pipeline, commit the regenerated `Assets/` together with the generator change.
- Never hand-edit GUIDs or `.meta` files. `.clonemap.json` and `asset_guids.json` are keyed state; do not rewrite them by hand.
- Blocks behave like the vanilla block they are cloned from; deviations are documented in `README.md`.
- Preview renders (`Source/Model/preview/`) stay on disk and are never committed. README images go in `docs/media/`.
- Run the SDK build and any publish step from the main checkout only, never from a git worktree.
- Vanilla reuse: cloned vanilla definitions and kit parts are fine in SE2 mods; nothing else from Keen.

## Commits and changelog

- Conventional Commits: `type(scope): summary` (feat, fix, docs, style, refactor, perf, test, build, ci, chore, revert). Release notes and the changelog are generated from them with git-cliff (`scripts/changelog.sh`).
- Sign off commits with `git commit -s` (DCO). The project is GPL-3.0. Outside contributors also sign the Rioku Labs CLA once (`CLA.md` in riokulabs/.github); the `cla` workflow checks it. Never add `actions/checkout` or any step that runs pull request code to `.github/workflows/cla.yml`.
- Optional hooks: `scripts/install-hooks.sh`.

## Never

- Never add AI attribution anywhere: no `Co-Authored-By` trailer for an AI tool, no "generated by/with" notes in commits, pull requests, code or docs.
- Never commit decompiled Keen code, Keen DLLs or other game binaries.
- Never copy Keen assets beyond the vanilla reuse this repo already documents, and never use third-party content that has no license.
- Never commit secrets or tokens (for example the SeMcp2 bearer token, Steam or GitHub credentials, `.env` files).
- Never push, tag or publish (GitHub, Steam Workshop, deploys) unless the maintainer asked for it in this session.
- Never modify the game install or the Steam library directories. Treat them as read-only.
- Never publish from a git worktree, and never run `se2mod.py build` with the game or Editor open.
- Never commit preview renders, `Content/`, or Blender files.
- Never rewrite published history or force-push shared branches.
